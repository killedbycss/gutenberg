# Конвертер шрифтов · OTF / TTF / WOFF / WOFF2

Модуль конвертации шрифтов между форматами с извлечением метрик, метаданных и
проверкой полноты набора символов. Бэкенд на Flask обрабатывает шрифты через
[fontTools](https://github.com/fonttools/fonttools); фронтенд на React даёт
загрузить файлы, выбрать целевые форматы и увидеть отчёт о каждом шрифте
(формат, метрики, лицензия, недостающие глифы).

## Что умеет

- **Конвертация между форматами** OTF, TTF, WOFF, WOFF2 (полная матрица).
- **Пакетный режим**: несколько файлов сразу → результат одним ZIP-архивом.
- **Извлечение метрик**: UPM, число глифов, насыщенность/ширина, вертикальные
  метрики (восходящая/нисходящая, интерлиньяж, высота прописных/строчных).
- **Метаданные и лицензия**: семейство, начертание, версия, автор + расшифровка
  `fsType` (разрешения на встраивание) — показываем, не блокируем.
- **Проверка полноты набора**: по категориям (латиница, кириллица, диакритика,
  пунктуация) с точным списком недостающих глифов. Два эталона — базовый и
  расширенный.

### Матрица конвертации

| Из \ В | OTF | TTF | WOFF | WOFF2 |
|--------|-----|-----|------|-------|
| **OTF** (CFF)  | пересохранение | CFF→glyf (cu2qu) | обёртка, CFF | обёртка, CFF |
| **TTF** (glyf) | glyf→CFF (best-effort) | пересохранение | обёртка, glyf | обёртка, glyf |
| **WOFF/WOFF2** | распаковка + при необходимости смена контуров | | | |

- **WOFF/WOFF2 — это контейнеры.** При конвертации в них тип контуров
  сохраняется: `OTF→WOFF2` остаётся CFF, `TTF→WOFF2` остаётся glyf. Смена
  математики кривых происходит только при цели OTF или TTF.
- **OTF→TTF** (кубика→квадратика, `cu2qu`) — надёжно.
- **TTF→OTF** (квадратика→кубика, `qu2cu` + CFF) — *best-effort*: направление
  редкое и по природе не повышающее точность; каждый такой результат
  сопровождается предупреждением. Проверяйте перед использованием.

## Структура

```
converter/
├── backend/                  Flask API + ядро на fontTools
│   ├── app.py                эндпоинты /api/analyze, /api/convert, /api/formats
│   ├── config.py             порт (5060) и лимиты (размер/кол-во файлов)
│   ├── fontkit/
│   │   ├── formats.py        детекция формата, обёртки WOFF/WOFF2, оркестрация
│   │   ├── outlines.py       конвертация контуров OTF↔TTF (cu2qu / qu2cu)
│   │   ├── report.py         метаданные, метрики, отчёт о покрытии
│   │   └── charsets.py       эталонные наборы символов (basic / extended)
│   ├── tests/                pytest: матрица конвертации, покрытие, ошибки
│   └── requirements.txt
└── frontend/                 React + Vite
    └── src/
        ├── App.jsx           состояние, загрузка, конвертация
        ├── api.js            обёртка над API
        ├── fontMeta.js       справочники (веса, ширины, форматирование)
        └── components/       Dropzone, FormatPicker, FontCard, Coverage, ResultBanner
```

## Запуск

### Бэкенд

```bash
cd backend
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
PORT=5060 ./.venv/bin/python app.py
```

API поднимется на `http://127.0.0.1:5060`. Порт 5060 выбран, чтобы не
конфликтовать с соседними модулями (typograph — 5050, spellcheck — 5001) и с
Control Center на macOS (5000).

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Vite стартует на `http://localhost:5174` и проксирует `/api` на бэкенд.

### Тесты

```bash
cd backend
./.venv/bin/python -m pytest
```

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET  | `/api/health`  | Живость + доступность WOFF2 (brotli) |
| GET  | `/api/formats` | Метаданные форматов и пресетов, лимиты |
| POST | `/api/analyze` | `fonts[]` (multipart) → отчёт по каждому файлу |
| POST | `/api/convert` | `fonts[]` + `targets[]` → ZIP + сводка в заголовке `X-Summary` |

`/api/convert` возвращает ZIP: сконвертированные файлы (при пакете — по папкам
на исходный файл) и `manifest.json` с деталями по каждому результату,
предупреждениями и ошибками. Компактная сводка дублируется в base64 в заголовке
`X-Summary`, чтобы фронт показал итог, не распаковывая архив.

## Границы модуля (осознанные решения)

- **Только конвертация форматов** — без интерполяции вариативных начертаний
  (генерации Medium из Light+Bold). При необходимости выделяется в отдельный
  модуль.
- **Недостающие глифы только репортятся**, шрифт не изменяется (без
  автогенерации и подстановки из донора).
- **Хинтинг сохраняется как есть** — не перегенерируется и не удаляется.
- **Обработка синхронная**: рассчитана на обычные шрифты; для очень крупных или
  массовых партий действуют лимиты (`MAX_FILE_SIZE`, `MAX_FILES` в `config.py`).
- **Коллекции (TTC/OTC) не поддерживаются** — разбирайте на отдельные шрифты.
- **Валидация результата** — структурная (результат перечитывается fontTools);
  автоматического сравнения рендера до/после нет.
