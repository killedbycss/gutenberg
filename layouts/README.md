# Макеты (`layouts`)

Модуль подбора и генерации макетов по назначению (пост, story, обложка, постер,
визитка). Пользователь загружает свой шрифт, выбирает назначение — система
рассчитывает выверенный макет (сетку, поля, кегли, расположение текста) из
**метрик шрифта** и типографских пропорций. Контент вставляется в готовые слоты,
результат экспортируется в PNG и самодостаточный SVG.

Часть семейства инструментов в `fonts/` (см. `converter`, `typograph`,
`spellcheck`, `studio`).

## Архитектура

Три слоя, намеренно разделённые, чтобы формульную генерацию можно было позже
дополнить библиотекой готовых шаблонов, не переписывая рендер:

```
  шрифт ─▶ [ backend/  тонкий сервис метрик (Flask + fontTools) ] ─▶ метрики JSON
                                                                        │
  назначение ──────────────────────────────────────────────────────────┤
                                                                        ▼
                              [ ПОДБОР  frontend/src/layout/engine.js ]  → LayoutSpec
                                    (formula@1; будущие template:<id>)      │
                                                                            ▼
                              [ РЕНДЕРИНГ  frontend/src/render/svg.js ]  → превью + PNG/SVG
```

- **`LayoutSpec`** (`frontend/src/layout/schema.js`) — единственный контракт между
  подбором и рендерингом. Координаты фреймов нормализованы (0..1), поэтому одна
  схема одинаково работает на 1080×1080 и на A3 и переносима между шаблонами.
  Поле `meta.generator` (`formula@1` / `template:<id>@1`) — шов: рендер один и тот
  же, меняется лишь источник схемы.
- **Подбор** (`engine.js`) — чистая функция `generateLayout()`; не знает о DOM.
- **Рендеринг** (`svg.js`) — `specToDrawOps()` (один расчёт) питает интерактивное
  превью (`components/Preview.jsx`) и статический экспорт (`buildSvgString`).

### Backend — только метрики

Тонкий сервис (`backend/`), одна задача — разобрать шрифт и вернуть метрики.
Вся логика подбора и рендеринга живёт на фронтенде (результат мгновенный, файл
не гоняется через сервер лишний раз).

| Метод | Путь | Назначение |
|-------|------|------------|
| GET  | `/api/health`  | живость + размер кэша |
| POST | `/api/metrics` | файл шрифта (поле `font`) → метрики JSON |

Результат кэшируется по SHA-256 содержимого файла (LRU). `cap-height` / `x-height`
берутся из таблицы OS/2 (v≥2); если их нет — измеряются геометрически по контурам
глифов «H» / «x»; если и это невозможно — типовая оценка. Источник помечается
полями `capHeightSource` / `xHeightSource` (`os2` | `geometric` | `fallback`).

## Формулы генерации (`formula@1`)

- **Оптический размер привязан к cap-height:** `fontSize = capPx / (capHeight/UPM)`,
  где `capPx = headlineCap × короткая_сторона`. Разные шрифты дают одинаковый
  видимый рост заголовка.
- **Иерархия кеглей** — модульная шкала: заголовок / `ratio` → подзаголовок /
  `ratio` → текст (`ratio` ≈ 1.35–1.5, задаётся назначением).
- **Интерлиньяж из метрик:** `natural = (ascent − descent + lineGap)/UPM`; для
  заголовка ≈ `natural×0.94`, для текста ≈ `natural×1.15`.
- **Поля** — доли сторон холста, заданы назначением.
- **Авто-подгонка:** если заголовок+подзаголовок+текст не помещаются по высоте,
  их кегли ужимаются единым коэффициентом — блоки не наезжают и не пропадают.
- **Композиция** — 3 варианта: «Заголовок сверху», «По центру», «Нижняя треть».

Назначения и коэффициенты — в `frontend/src/layout/purposes.js`.

## Запуск

Одним кликом (macOS): `./start.command` — поднимет backend (:5070), frontend
(:5175) и откроет браузер.

Вручную:

```bash
# backend
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python app.py            # http://127.0.0.1:5070

# frontend (в другом терминале)
cd frontend
npm install
npm run dev                        # http://localhost:5175
```

Тесты бэкенда: `cd backend && .venv/bin/python -m pytest`.

## Границы v1 (и заделы на будущее)

- Шрифт — **загрузкой пользователя** (свой файл). Реестр встроенных «готовых»
  шрифтов не заполнен, но заложен: достаточно положить файлы + их метрики.
- Экспорт — **скачивание** PNG + самодостаточный SVG (шрифт встроен data-URL).
  Серверного шеринга по ссылке нет, но `LayoutSpec` сериализуем — эндпоинт
  «сохранить/получить по ссылке» добавляется без изменения рендера.
- Всё считается в **экранных px / RGB**. Печать (мм, 300 dpi, вылеты, CMYK, PDF) —
  отдельный шаг; поля `canvas.unit` / `canvas.dpi` под это уже зарезервированы.
- Готовые дизайнерские **шаблоны** подключаются через тот же `LayoutSpec`
  (`meta.generator = template:<id>`).
- Интеграция со **studio** (4-я вкладка) и с редактором шрифтов (приём по
  `fontRef`) — по образцу остальных модулей.
